Správa softvéru

Inštalácia, aktualizácia a odstraňovanie programov cez balíkový systém.

Teória 15 min Prax 35 min Úloha 10 min

19.1 Čo je balíkový systém?

Balíkový systém je nástroj, ktorým sa v Linuxe inštalujú, aktualizujú a odstraňujú programy. Nemusíš nikam chodiť na web, sťahovať .exe súbory a klikať "Next". Všetko sa dá z terminálu.

Každý program je zabalený do balíka. Balíky sa ukladajú na serveri, ktorý sa volá repozitár. Keď napíšeš príkaz na inštaláciu, systém stiahne balík z repozitára, rozbalí ho a umiestni súbory na správne miesta. Automaticky vyrieši aj závislosti (ďalšie balíky, ktoré ten program potrebuje).

Rôzne distribúcie používajú rôzne balíkové systémy:

DistribúciaSprávca balíkovPríkaz
Debianaptapt install nazov
Linux Mintaptapt install nazov
Fedoradnfdnf install nazov

Na našom krúžku sú zmiešané distribúcie, takže si ukážeme oba varianty. Príkazy sú takmer identické, líši sa len názov správcu balíkov.

19.2 Aktualizácia systému

Pred akoukoľvek inštaláciou by si mal aktualizovať zoznam balíkov. Tým sa stiahne najnovší zoznam dostupných programov a ich verzií.

Debian / Mint
student@debian:~$ sudo apt update Hit:1 http://deb.debian.org/debian bookworm InRelease Hit:2 http://deb.debian.org/debian bookworm-updates InRelease Hit:3 http://security.debian.org/debian-security bookworm-security InRelease Reading package lists... Done student@debian:~$
Fedora
student@fedora:~$ sudo dnf check-update Last metadata expiration check: 0:05:12 ago on Thu Sep 8 10:00:00 2026. Updates metadata is up to date. student@fedora:~$

apt update iba stiahne zoznam, nič neinštaluje. Až apt upgrade nainštaluje samotné aktualizácie. Je to rozdiel: update = aktualizuj zoznam, upgrade = nainštaluj aktualizácie.

Debian / Mint
student@debian:~$ sudo apt upgrade -y Reading package lists... Done Building dependency tree... Done Reading state information... Done Calculating upgrade... Done 0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded. student@debian:~$
Fedora
student@fedora:~$ sudo dnf upgrade -y Last metadata expiration check: 0:10:34 ago on Thu Sep 8 10:00:00 2026. Dependencies resolved. Nothing to do. Complete! student@fedora:~$
Vždy najprv update!
Pred inštaláciou alebo upgrade vždy spusti apt update (alebo dnf check-update). Bez toho môže systém hľadať balíky podľa starého zoznamu a nenájde ich, alebo nainštaluje staršiu veriu.

19.4 Odstraňovanie programov

Ak program už nepotrebuješ, môžeš ho odstrániť. Dva príkazy: remove odstráni balík, ale ponechá konfiguračné súbory. purge odstráni všetko vrátane konfigurácie.

Debian / Mint
student@debian:~$ sudo apt remove tree -y Reading package lists... Done Building dependency tree... Done The following packages will be REMOVED: tree 0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded. student@debian:~$
Fedora
student@fedora:~$ sudo dnf remove tree -y Last metadata expiration check: 0:30:00 ago on Thu Sep 8 10:00:00 2026. Dependencies resolved. ================================================================================ Package Architecture Version Repository Size ================================================================================ Removing: tree x86_64 2.1.1-5.fc40 @fedora 181 k Transaction Summary ================================================================================ Remove 1 Package student@fedora:~$
remove vs. purge
apt remove (alebo dnf remove) odstráni program, ale nechá jeho konfiguráciu v systéme. apt purge odstráni úplne všetko. Ak chceš program nainštalovať znova a ponechať si nastavenia, stačí remove. Ak ho chceš zmazať aj s konfiguráciou, použi purge.

Hodina 20 · Blok 5

Procesy

Čo sa deje v pozadí systému, ako sledovať a riadiť spustené programy.

Teória 15 min Prax 35 min Úloha 10 min

20.1 Čo je proces?

Keď spustíš akýkoľvek program v Linuxe, vytvorí sa proces. Proces je program, ktorý práve beží. Každý proces má svoje číslo (PID) a vie, aký proces ho spustil (PPID).

  • PID (Process ID) - jedinečné číslo každého procesu
  • PPID (Parent Process ID) - PID procesu, ktorý ho spustil
  • UID (User ID) - používateľ, ktorému proces patrí

Na sledovanie a ovládanie procesov slúžia príkazy ps, top, htop, kill a ďalšie.

20.2 Zobrazenie procesov

student@debian: ~
student@debian:~$ ps PID TTY TIME CMD 1234 pts/0 00:00:00 bash 5678 pts/0 00:00:00 ps student@debian:~$

Bazické ps ukáže iba procesy v aktuálnom termináli. To málo stačí. Omnoho užitočnejší je:

student@debian: ~
student@debian:~$ ps aux USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND root 1 0.0 0.2 169404 11200 ? Ss Sep07 0:12 /sbin/init root 2 0.0 0.0 0 0 ? S Sep07 0:00 [kthreadd] student 1234 0.0 0.1 22836 5400 pts/0 Ss 10:00 0:00 -bash student 1235 0.0 0.0 38468 3200 pts/0 R+ 10:30 0:00 ps aux student@debian:~$

Príznak aux znamená: a = všetky procesy, u = pre používateľa, x = aj bez terminálu. Alternatíva:

student@debian: ~
student@debian:~$ ps -ef | head -5 UID PID PPID C STIME TTY TIME CMD root 1 0 0 Sep07 ? 00:00:12 /sbin/init root 2 0 0 Sep07 ? 00:00:00 [kthreadd] root 3 2 0 Sep07 ? 00:00:00 [pool_workqueue_release] root 4 2 0 Sep07 ? 00:00:00 [kworker/R-inode_wb] student@debian:~$
ps aux vs. ps -ef
Oba príkazy ukážu všetky procesy. Rozdiel je len v formáte výstupu. ps aux zobrazuje percentuálnu spotrebu CPU a RAM, ps -ef ukazuje PPID (rodičovský proces). Používaj ten, ktorý ti viac vyhovuje.

20.3 Interaktívne sledovanie: top a htop

Namiesto statického výpisu môžeš sledovať procesy v reálnom čase:

student@debian: ~
student@debian:~$ htop 1 [||||||||||||||||||||||||||||||||||||||100.0%] Tasks: 87 total, 1 running 2 [||||||||||||||||||||||||||||||||||||||100.0%] Load average: 0.52 0.38 0.29 3 [||||||||||||||||||||||||||||||||||||||100.0%] Uptime: 01:23:45 Mem[||||||||||||||| 420Mi/3.8Gi] Swp[| 0B/2.0Gi] PID USER PRI NI VIRT RES SHR S CPU% MEM% TIME+ Command 1 root 20 0 169M 11M 8.2M S 0.0 0.3 0:12.34 /sbin/init 1234 student 20 0 22836 5.4M 4.1M S 0.0 0.1 0:00.12 -bash student@debian:~$

htop je farebný, intuitívny a dá sa ovládať šípkami a klávesmi. Pre ukončenie stlač q.

top funguje podobne, ale je menej prehľadný. Oba ukazujú: koľko procesov beží, ako veľmi sa používa CPU a RAM, ktoré procesy žerú najviac zdrojov.

20.4 Zabíjanie procesov

Ak proces zbesí alebo ho chceš ukončiť, použiješ kill. Potrebuješ PID procesu:

student@debian: ~
student@debian:~$ sleep 300 & [1] 6789 student@debian:~$ ps aux | grep sleep student 6789 0.0 0.0 3212 1024 pts/0 S 10:35 0:00 sleep 300 student 6790 0.0 0.0 6544 1536 pts/0 S+ 10:35 0:00 grep --color=auto sleep student@debian:~$ kill 6789 student@debian:~$ ps aux | grep sleep student 6791 0.0 0.0 6544 1536 pts/0 S+ 10:36 0:00 grep --color=auto sleep # Proces zmizol - zostal iba grep student@debian:~$

Ak normálne kill nepomôže (proces nereaguje), použijeme silnejší signál:

student@debian: ~
student@debian:~$ kill -9 6789 # SIGKILL - okamžite zabije proces student@debian:~$ pkill sleep # Zabije všetky procesy s názvom "sleep" student@debian:~$
kill -9 je posledná možnosť
Normálne kill (bez prepínača) pošle procesu signál SIGTERM a nechá ho korektne skončiť. kill -9 (SIGKILL) proces okamžite ukončí bez možnosti uložiť dáta. Používaj kill bez -9 vždy, keď to ide. -9 až keď nič iné nefunguje.

20.5 Úlohy na pozadí

Pomocník & spustí príkaz na pozadí. Ctrl+Z pozastaví proces. jobs ukáže zoznam pozastavených/odložených úloh. fg vráti poslednú úlohu do popredia. bg ju spustí na pozadí.

student@debian: ~
student@debian:~$ sleep 60 & [1] 7890 student@debian:~$ sleep 120 & [2] 7891 student@debian:~$ jobs [1]+ Running sleep 60 & [2]- Running sleep 120 & student@debian:~$ kill 7890 student@debian:~$ jobs [1]+ Terminated sleep 60 & [2]- Running sleep 120 & student@debian:~$

Ak chceš, aby príkaz bežal aj po odhlásení z terminálu, použi nohup:

student@debian: ~
student@debian:~$ nohup sleep 3600 & [3] 7892 nohup: appending output to 'nohup.out' student@debian:~$
Zhrnutie signálov
kill PID = jemné ukončenie (SIGTERM). kill -9 PID = okamžité ukončenie (SIGKILL). pkill nazov = zabiť všetky procesy podľa názvu. killall nazov = to isté, ale presnejšie.

  3. Čo sa stane, keď spustíš príkaz s & na konci? A čo spraví Ctrl+Z?

Hodina 21 · Blok 5

Služby a systemd

Správa služieb na pozadí, logovanie a riadenie systému cez systemd.

Teória 15 min Prax 35 min Úloha 10 min

21.1 Čo je systemd?

Keď sa Linux spustí, systemd je prvý proces (PID 1), ktorý naštartuje všetko ostatné. Stará sa o služby (services), ako je SSH, sieť, tlačiareň a ďalšie programy, ktoré bežia na pozadí.

Servis (service) je program, ktorý beží na pozadí a čaká na požiadavky. Príklady:

  • sshd - server pre vzdialené pripojenie cez SSH
  • cron - plánovač úloh
  • NetworkManager - správa siete
  • cups - tlačiarenský server

Každá služba je opísaná v súbore jednotky (unit file), typicky v adresári /etc/systemd/system/. Ovládame ju cez príkaz systemctl.

21.2 Kontrola stavu služieb

student@debian: ~
student@debian:~$ systemctl status ssh ● ssh.service - OpenBSD Secure Shell server Loaded: loaded (/lib/systemd/system/ssh.service; enabled; preset: enabled) Active: active (running) since Thu 2026-09-08 09:45:12 CEST; 1h 15min ago Docs: man:sshd(8) man:sshd_config(5) Process: 567 ExecStartPre=/usr/sbin/sshd -t (code=exited, status=0/SUCCESS) Main PID: 789 (sshd) Tasks: 1 (limit: 4607) Memory: 5.2M CPU: 120ms CGroup: /system.slice/ssh.service └─789 "sshd: /usr/sbin/sshd -D [listener] 10 of 10-100 startups" student@debian:~$

Vidíš tri dôležité veci: Loaded (kde je konfigurácia, či je zapnutý pri štarte), Active (že práve beží), a Main PID (číslo hlavného procesu).

student@debian: ~
student@debian:~$ systemctl --failed UNIT LOAD ACTIVE SUB DESCRIPTION ● ssh.service loaded failed failed OpenBSD Secure Shell server 0 loaded units listed. student@debian:~$

Príkaz systemctl --failed ukáže iba služby, ktoré zlyhali. Ak je zoznam prázdny, systém je v poriadku.

21.3 Štart, stop, reštart

Základné ovládanie služieb:

PríkazČo robí
systemctl start nazovSpustí službu hneď
systemctl stop nazovZastaví službu
systemctl restart nazovZastaví a spustí znova
systemctl enable nazovZapne službu pri štarte systému
systemctl disable nazovVypne službu pri štarte systému
student@debian: ~
student@debian:~$ sudo systemctl restart ssh student@debian:~$ systemctl status ssh ● ssh.service - OpenBSD Secure Shell server Loaded: loaded (/lib/systemd/system/ssh.service; enabled; preset: enabled) Active: active (running) since Thu 2026-09-08 11:05:33 CEST; 3s ago student@debian:~$
enable vs. start
systemctl start spustí službu len teraz. systemctl enable nastaví, aby sa služba spustila automaticky pri každom zapnutí systému. Ak chceš niečo spustiť teraz aj pri bootovaní, použi obe: systemctl enable --now nazov.

21.4 Časovanie a logy

systemd-analyze blame ukáže, ako dlho trvalo spustenie jednotlivých služieb. Hodí sa, keď chceš zistiť, prečo sa systém dlho štartuje.

student@debian: ~
student@debian:~$ systemd-analyze blame | head -5 8.123s NetworkManager-wait-online.service 3.456s plymouth-quit-wait.service 1.234s dev-sda6.device 0.890s accounts-daemon.service 0.567s ModemManager.service student@debian:~$

Pre logy (záznamy) systému použijeme journalctl:

student@debian: ~
student@debian:~$ journalctl -u ssh --no-pager -n 10 Sep 08 10:00:12 debian sshd[789]: Server listening on 0.0.0.0 port 22. Sep 08 10:00:12 debian sshd[789]: Server listening on :: port 22. Sep 08 10:05:45 debian sshd[1023]: Accepted publickey for student from 192.168.1.100 Sep 08 10:05:45 debian sshd[1023]: pam_unix(sshd:session): session opened for user student student@debian:~$
student@debian: ~
student@debian:~$ journalctl -f -- Logs begin at Thu 2026-09-08 09:45:12 CEST. -- Sep 08 11:10:01 debian CRON[9012]: (student) CMD (test -x /usr/sbin/anacron || ...) Sep 08 11:10:15 debian kernel: [12345.678] USB disconnect, address 2 # Stlač Ctrl+C pre ukončenie student@debian:~$

Príkaz journalctl -f sleduje logy v reálnom čase, rovnako ako tail -f pre súbory. Ukončíš ho Ctrl+C.

root oprávnenia
Na ovládanie služieb potrebuješ sudo. Čítanie logov cez journalctl väčšinou funguje aj ako normálny používateľ, ale niekedy potrebuješ sudo journalctl pre staršie záznamy.

Hodina 22 · Blok 5

Cron a plánovač

Automatické spúšťanie príkazov a skriptov v naplánovanom čase.

Teória 10 min Prax 30 min Úloha 10 min

22.1 Čo je cron?

Cron je plánovač úloh v Linuxe. Umožňuje naplánovať spúšťanie príkazov alebo skriptov v presne určenom čase. Nastavíš raz a funguje automaticky, bez tvojho zásahu.

Služba cron (alebo crond) beží na pozadí. Každú minútu kontroluje, či niektorý naplánovaný príkaz má prísť na rad. Ak áno, spustí ho.

Nastavenia sa ukladajú do crontab (cron tabuľka). Každý používateľ má svoj vlastný crontab.

22.2 Práca s crontabom

student@debian: ~
student@debian:~$ crontab -l no crontab for student student@debian:~$ crontab -e # Otvorí sa editor (nano alebo vim), kde napíšeš pravidlá student@debian:~$
PríkazČo robí
crontab -eOtvorí crontab na úpravu
crontab -lVypíše obsah crontabu
crontab -rOdstráni celý crontab (pozor!)

22.3 Syntax cron riadku

Každý riadok v crontabe má túto štruktúru:

minúta hodina deň mesiac deň_týždňa príkaz

PozíciaRozsahPríklad
minúta0 - 5930
hodina0 - 238
deň1 - 3115
mesiac1 - 126
deň_týždňa0 - 7 (0 a 7 = nedeľa)1
príkazakýkoľvek príkaz alebo skript/home/student/zaloha.sh

Znak * znamená "každý". Špeciálne znaky: */5 = každých 5, 1,15 = 1. a 15., 1-5 = od 1 do 5.

22.4 Praktické príklady

Otvor crontab cez crontab -e a pridaj tieto riadky:

crontab
# Spustiť zálohu každý deň o 3:00 v noci 0 3 * * * /home/student/zaloha.sh # Spustiť report každý pondelok o 8:00 0 8 * * 1 /home/student/report.sh # Vypísať dátum každú hodinu do logu 0 * * * * echo "$(date)" >> /tmp/hodiny.log # Test: spustiť každú minútu (pre testovanie, potom zmazať!) * * * * * echo "Test $(date)" >> /tmp/cron_test.log student@debian:~$
Výpis crontabu
Po uložení (v nano: Ctrl+O, Enter, Ctrl+X) over príkazom crontab -l, že sa riadky uložili správne.

22.5 Cron zo zálohy z hodiny 17

Na hodine 17 sme napísali zálohovací skript. Teraz ho naplánujeme, aby sa spúšťal automaticky:

student@debian: ~
student@debian:~$ ls -la ~/zaloha.sh -rwxr-xr-x 1 student student 256 Sep 7 12:00 /home/student/zaloha.sh student@debian:~$ crontab -l # Spustiť zálohu každý deň o 3:00 0 3 * * * /home/student/zaloha.sh student@debian:~$

Predtým, než založíš cron, otestuj skript manuálne:

student@debian: ~
student@debian:~$ bash ~/zaloha.sh Záloha vytvorená: backup_2026-09-08.tar.gz student@debian:~$ ls ~/zalohy/ backup_2026-09-08.tar.gz student@debian:~$
Vždy testuj pred cron
Nikdy nenastavuj cron pre skript, ktorý si predtým nespustil manuálne. Ak má skript chybu, cron ju bude opakovať každý deň a možno si to nevšimneš.

22.6 Logy cronu

Ako zistíš, či cron naozaj spustil tvoj príkaz?

student@debian: ~
student@debian:~$ systemctl status cron ● cron.service - Regular background program processing daemon Loaded: loaded (/lib/systemd/system/cron.service; enabled; preset: enabled) Active: active (running) since Thu 2026-09-08 09:45:12 CEST; 1h 30min ago student@debian:~$ journalctl -u cron --no-pager -n 10 Sep 08 09:45:12 debian cron[456]: (CRON) INFO (pidfile fd = 3) Sep 08 09:45:12 debian cron[456]: (CRON) INFO (Running @reboot jobs) Sep 08 10:00:01 debian CRON[7890]: (student) CMD (echo "$(date)" >> /tmp/hodiny.log) Sep 08 11:00:01 debian CRON[8012]: (student) CMD (echo "$(date)" >> /tmp/hodiny.log) student@debian:~$
student@debian: ~
student@debian:~$ cat /tmp/hodiny.log Thu Sep 8 10:00:01 CEST 2026 Thu Sep 8 11:00:01 CEST 2026 student@debian:~$
Rýchle testovanie
Ak chceš otestovať cron bez čakania, nastav čas o 1-2 minúty v budúcnosti, pridaj riadok do crontabu, počkaj, over výstup a potom riadok zmaž. Príkaz crontab -r odstráni celý crontab, radšej uprav cez crontab -e a vymaž len ten riadok.
