Hodina 23 · Blok 6

Základy siete

IP adresy, gateway, DNS a prvé sieťové príkazy.

Teória 15 min Prax 30 min Úloha 10 min

23.1 Čo je IP adresa?

Každý počítač v sieti má svoju adresu, podobne ako dom má číslo. Bez nej by sa dáta nemali kam doručiť.

IP adresa je číslo, napríklad 192.168.1.10. localhost je špeciálna adresa 127.0.0.1, ktorá vždy ukazuje na tvoj vlastný počítač. Gateway je brána, cez ktorú sa dostaneš von do internetu, a DNS prekladá mená ako google.com na IP adresy.

localhost
localhost je vždy 127.0.0.1 a ukazuje na tvoj vlastný počítač. Každý počítač v sieti má unikátnu IP adresu, aby sa dáta doručili správnemu stroju.

23.2 Zisti svoju IP a gateway

Príkaz ip je moderný nástroj na správu siete. ip a ukáže všetky sieťové rozhrania a ich adresy.

student@debian: ~
student@debian:~$ ip a 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 inet 127.0.0.1/8 scope host lo 2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 inet 192.168.1.10/24 brd 192.168.1.255 scope global enp0s3 student@debian:~$ ip route default via 192.168.1.1 dev enp0s3 192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.10 student@debian:~$

lo je loopback rozhranie (localhost). enp0s3 je tvoja skutočná sieťová karta. Riadok default via 192.168.1.1 ti hovorí, že gateway je 192.168.1.1.

23.3 Ping a traceroute

ping pošle testovací paket a čaká na odpoveď. Najprv otestujeme localhost, potom sa pozrieme von do internetu.

student@debian: ~
student@debian:~$ ping -c 4 localhost PING localhost (127.0.0.1) 56(84) bytes of data. 64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.028 ms 64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.031 ms --- localhost ping statistics --- 4 packets transmitted, 4 received, 0% packet loss student@debian:~$ ping -c 4 1.1.1.1 PING 1.1.1.1 (1.1.1.1) 56(84) bytes of data. 64 bytes from 1.1.1.1: icmp_seq=1 ttl=58 time=12.4 ms 64 bytes from 1.1.1.1: icmp_seq=2 ttl=58 time=11.9 ms --- 1.1.1.1 ping statistics --- 4 packets transmitted, 4 received, 0% packet loss student@debian:~$

-c 4 obmedzí počet paketov na štyri, inak by ping bežal donekonečna. 1.1.1.1 je verejný DNS server Cloudflare, dobrý na test, či máš internet.

student@debian: ~
student@debian:~$ tracepath 1.1.1.1 1?: [LOCALHOST] pmtu 1500 1: 192.168.1.1 0.412ms 2: 10.0.0.1 1.203ms 3: 89.173.0.1 8.451ms 4: 1.1.1.1 12.300ms reached student@debian:~$

tracepath (alebo traceroute) ukáže cestu, ktorou paket prechádza cez jednotlivé routery až k cieľu. Každý riadok je jeden skok v sieti.

23.4 Počúvajúce porty a hostname

ss -tln ukáže, ktoré služby na tvojom počítači počúvajú na sieťových portoch. hostname ti povie názov stroja.

student@debian: ~
student@debian:~$ ss -tln State Recv-Q Send-Q Local Address:Port Peer Address:Port LISTEN 0 128 0.0.0.0:22 0.0.0.0:* LISTEN 0 128 127.0.0.1:631 0.0.0.0:* student@debian:~$ hostname debian student@debian:~$ cat /etc/hosts 127.0.0.1 localhost 127.0.1.1 debian student@debian:~$

Port 22 počúva SSH, port 631 tlačiareň. Súbor /etc/hosts je lokálna tabuľka mien, ktorá sa prečíta skôr ako DNS. Zatiaľ ho len ukazujeme, neupravujeme.

Zapamätaj si
ip a ukáže IP adresy, ip route gateway, ping testuje spojenie a ss -tln ukáže počúvajúce porty. Tieto štyri príkazy sú základ každého sieťového admina.

Hodina 24 · Blok 6

SSH

Vzdialená správa serverov cez Secure Shell.

Teória 15 min Prax 30 min Úloha 10 min

24.1 Čo je SSH?

SSH (Secure Shell) je šifrovaný protokol na vzdialenú správu počítačov. Správcovia serverov sa takto pripájajú na stroje, ktoré nemajú žiadny monitor.

Keď sa pripojíš cez SSH, dostaneš terminál vzdialeného počítača, akoby si pri ňom sedel. Všetko, čo pošleš, je šifrované, takže nikto na ceste nevidí tvoje heslá ani príkazy.

24.2 Prvé pripojenie

Pripojenie má tvar ssh používateľ@ip. Skúsime sa pripojiť sami na seba - na localhost. Je to plnohodnotné SSH spojenie, len vzdialený stroj si ty sám.

student@debian: ~
student@debian:~$ ssh student@localhost The authenticity of host 'localhost (127.0.0.1)' can't be established. ED25519 key fingerprint is SHA256:5rXk9v2QpLm8TnW1cYb... Are you sure you want to continue connecting (yes/no/[fingerprint])? yes Warning: Permanently added 'localhost' (ED25519) to the list of known hosts. student@localhost's password: ******** Linux debian 6.1.0-25-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.112-1 x86_64 student@debian:~$ hostname debian student@debian:~$ exit logout Connection to localhost closed. student@debian:~$

Pri prvom pripojení sa ťa systém pýta, či dôveruješ serveru - jeho odtlačok (fingerprint) si uloží do ~/.ssh/known_hosts a nabudúce sa už nepýta. Odpovieš yes a zadáš heslo. Prompt vyzerá rovnako, ale si už v druhej, vzdialenej relácii - exit ťa vráti do tej pôvodnej.

Prečo nie ssh root@...?
Skúsiť sa prihlásiť ako root cez SSH heslom na Debiane nevyjde - v /etc/ssh/sshd_config je predvolene PermitRootLogin prohibit-password, teda root sa heslom prihlásiť nesmie. Je to zámer a je to dobre: root cez SSH je prvá vec, ktorú skúšajú útočníci. Prihlás sa ako bežný používateľ a použi sudo, presne ako na hodine 9.

24.3 Inštalácia SSH servera

Ak SSH server nemáš nainštalovaný, nainštalujeme ho. Na Debiane a Minte cez apt, na Fedore cez dnf.

student@debian: ~
student@debian:~$ sudo apt install openssh-server Reading package lists... Done Building dependency tree... Done openssh-server is already the newest version. student@debian:~$ sudo systemctl enable ssh Synchronizing state of ssh.service with SysV service script. student@debian:~$ sudo systemctl status ssh ● ssh.service - OpenBSD Secure Shell server Loaded: loaded (/lib/systemd/system/ssh.service; enabled) Active: active (running) student@debian:~$
student@fedora: ~
student@fedora:~$ sudo dnf install openssh-server Last metadata expiration check: 1:12:34 ago. Package openssh-server-9.6p1-3.fc40.x86_64 is already installed. student@fedora:~$ sudo systemctl enable --now sshd Created symlink /etc/systemd/system/multi-user.target.wants/sshd.service. student@fedora:~$

systemctl enable zabezpečí, že sa služba spustí aj po reštarte. Na Fedore sa služba volá sshd, na Debiane ssh.

24.4 SSH kľúče

Heslá sa dajú uhádnuť. Kľúče sú bezpečnejšie. Vygeneruješ si pár: súkromný kľúč (necháš si ho) a verejný kľúč (nakopíruješ na server).

student@debian: ~
student@debian:~$ ssh-keygen -t ed25519 Generating public/private ed25519 key pair. Enter file in which to save the key (/home/student/.ssh/id_ed25519): Enter Enter passphrase (empty for no passphrase): Enter Your identification has been saved in /home/student/.ssh/id_ed25519 Your public key has been saved in /home/student/.ssh/id_ed25519.pub student@debian:~$ ssh-copy-id student@localhost /usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s) student@localhost's password: ******** Number of key(s) added: 1 student@debian:~$ ssh student@localhost # tentoraz sa na heslo uz nepyta Linux debian 6.1.0-25-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.112-1 x86_64 student@debian:~$ exit logout student@debian:~$

Po nakopírovaní kľúča sa pripojíš bez zadávania hesla. ssh-copy-id ti verejný kľúč pridá do súboru ~/.ssh/authorized_keys na serveri.

Nikdy nezdieľaj súkromný kľúč
Súkromný kľúč ~/.ssh/id_ed25519 (alebo id_rsa) je tvoja identita. Kto ho má, môže sa za teba prihlásiť. Verejný kľúč .pub môžeš zdieľať, súkromný nikdy.

24.5 SCP - kopírovanie súborov

scp kopíruje súbory medzi počítačmi cez SSH. Funguje ako cp, ale s adresou vzdialeného stroja.

student@debian: ~
student@debian:~$ echo "ahoj" > poznamka.txt student@debian:~$ scp poznamka.txt student@localhost:/tmp/ poznamka.txt 100% 5 0.1KB/s 00:00 student@debian:~$ scp -r moj_adresar student@localhost:/tmp/ moj_adresar/subor1.txt 100% 12 0.2KB/s 00:00 moj_adresar/subor2.txt 100% 34 0.3KB/s 00:00 student@debian:~$

scp -r kopíruje celý adresár rekurzívne. Smer šípky určuje smer kopírovania: z lokálneho na vzdialený, alebo naopak.

Hodina 25 · Blok 6

Súborové systémy

Disky, mountovanie a miesto na disku.

Teória 15 min Prax 30 min Úloha 10 min

25.1 Čo je mount a súborový systém?

Súborový systém určuje, ako sú dáta uložené na disku. Linux najčastejšie používa ext4. Mount znamená pripojiť disk do adresárovej štruktúry.

Na rozdiel od Windowsu, kde má každý disk písmeno, v Linuxe sa disky pripájajú do existujúcich adresárov. Napríklad tvoj hlavný disk je pripojený na / a swap je špeciálny oddiel, ktorý slúži ako virtuálna pamäť (diskový doplnok RAM).

25.2 lsblk a blkid

lsblk ukáže disky a oddiely v prehľadnej stromovej štruktúre. blkid ukáže identifikátory oddielov.

student@debian: ~
student@debian:~$ lsblk NAME MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS sda 8:0 0 20G 0 disk ├─sda1 8:1 0 512M 0 part /boot/efi ├─sda2 8:2 0 18G 0 part / └─sda3 8:3 0 1.5G 0 part [SWAP] student@debian:~$ sudo blkid /dev/sda2: UUID="a1b2c3d4-..." TYPE="ext4" PARTUUID="..." /dev/sda3: UUID="e5f6a7b8-..." TYPE="swap" PARTUUID="..." student@debian:~$

Vidíš disk sda s tromi oddielmi: boot, hlavný systém na ext4 a swap. MOUNTPOINTS ukazuje, kam je ktorý oddiel pripojený.

25.3 Miesto na disku

df -h ukáže voľné miesto na všetkých pripojených systémoch. du ukáže, koľko miesta zaberajú adresáre.

student@debian: ~
student@debian:~$ df -h Filesystem Size Used Avail Use% Mounted on /dev/sda2 18G 6.2G 11G 37% / tmpfs 1.9G 0 1.9G 0% /dev/shm student@debian:~$ du -sh * 4.0K Dokumenty 1.2G Downloads 8.0K poznamka.txt 340M Projekty student@debian:~$ du -sh . 1.6G . student@debian:~$

-h znamená human-readable, teda čitateľné veľkosti ako 1.2G. du -sh * ukáže veľkosť každého súboru a adresára v aktuálnom priečinku, du -sh . celkovú veľkosť aktuálneho adresára.

25.4 Mount a fstab

mount bez argumentov ukáže všetky aktuálne pripojené systémy. Súbor /etc/fstab definuje, čo sa pripojí pri štarte.

student@debian: ~
student@debian:~$ mount | head -5 /dev/sda2 on / type ext4 (rw,relatime) proc on /proc type proc (rw,nosuid) sysfs on /sys type sysfs (rw,nosuid) devtmpfs on /dev type devtmpfs (rw,nosuid) student@debian:~$ cat /etc/fstab UUID=a1b2c3d4-... / ext4 errors=remount-ro 0 1 UUID=e5f6a7b8-... none swap sw 0 0 student@debian:~$
/etc/fstab NEUPRAVOVAŤ
Súbor /etc/fstab riadi, čo sa pripojí pri štarte systému. Chyba v ňom môže spôsobiť, že sa systém nespustí. Nikdy ho neupravuj bez dozoru učiteľa.

25.5 Vytvor a odstráň testovací súbor

dd vytvorí súbor presnej veľkosti. Vytvoríme 100 MB testovací súbor a hneď ho odstránime.

student@debian: ~
student@debian:~$ dd if=/dev/zero of=/tmp/test bs=1M count=100 100+0 records in 100+0 records out 104857600 bytes (105 MB, 100 MiB) copied, 0.12 s, 873 MB/s student@debian:~$ ls -lh /tmp/test -rw-r--r-- 1 student student 100M Sep 8 10:30 /tmp/test student@debian:~$ rm /tmp/test student@debian:~$

if=/dev/zero znamená vstup plný núl, bs=1M veľkosť bloku a count=100 počet blokov, teda 100 MB. Súbor sme hneď odstránili, aby sme nezaplnili disk.

25.6 Prehľad súborových systémov

Na disku môže byť viac formátov a každý má inú filozofiu. Toto sú tie, na ktoré v Linuxe najčastejšie narazíš.

FormátKde ho stretnešPoznámka
ext4systémový disk / a /homemoderný žurnalovací súborový systém, natívny pre Linux, dnešný štandard
ext2staršie systémy, embeddedbez žurnalovania, výborná podpora v jadre
btrfs/home, /var, NAS serveryžurnalovací, podporuje snapshoty
xfsveľké dáta, serverové diskysilný žurnalovací FS, bežný na Linux serveroch
swapswapovací súbor/partíciadisková virtuálna pamäť (paging), dnes častejšie swapfile (obdoba pagefile.sys vo Windows)

Ktorý si vybrať?
Pre systémový disk ext4, pre zdieľané dáta medzi OS NTFS/exFAT, pre snapshoty btrfs.

Súborový systém disku sa mení formátovaním, ktoré zmaže všetky dáta. Nikdy neformátuj disk, ktorého obsah nechceš stratiť. Na kurze to nepotrebuješ robiť.

Hodina 26 · Blok 6

Nano a vim

Textové editory priamo v termináli.

Teória 10 min Prax 30 min Úloha 10 min

26.1 Prečo editor v termináli?

Na serveri nemáš grafické prostredie. Keď sa pripojíš cez SSH, jediný spôsob, ako upraviť konfiguračný súbor, je textový editor v termináli.

Naučíš sa dva: nano je jednoduchý a priateľský, vim je výkonný, ale má strmú krivku učenia. Oba nájdeš na každom Linuxe.

26.2 Nano - priateľský editor

Nano otvoríš príkazom nano súbor. Dole v okne vidíš klávesové skratky. Ctrl+O uloží, Ctrl+X ukončí, Ctrl+W hľadá.

student@debian: ~
student@debian:~$ nano poznamky.txt GNU nano 7.2 poznamky.txt Ahoj, toto su moje poznamky z hodiny. Dnes sme sa ucili nano a vim. ^G Nápoveda ^O Uložiť ^W Hľadať ^X Ukončiť student@debian:~$

V nano píšeš rovno, žiadne módy. Ctrl+O ťa opýta na názov súboru, stlačíš Enter a je uložený. Ctrl+X ťa vráti do terminálu.

26.3 Vim - výkonný, ale náročný

Vim má dva hlavné módy: normal a insert. V normal móde naviguješ a vydávaš príkazy, v insert móde píšeš text. i ťa prepne do insert, Esc vždy vráti do normal.

Vim má módy
Vim má módy: insert a normal. Esc ti vždy vráti normal mód. Ak si sa zasekol, stlač Esc a si v bezpečí.
student@debian: ~
student@debian:~$ vim poznamky.txt Ahoj, toto su moje poznamky z hodiny. Dnes sme sa ucilo nano a vim. ~ ~ ~ -- INSERT -- student@debian:~$

Po otvorení si v normal móde. Stlač i a začni písať. Keď skončíš, stlač Esc, napíš :wq a Enter pre uloženie a ukončenie. :q! ukončí bez uloženia.

26.4 Základné vim príkazy

Pár príkazov, ktoré ti ušetria veľa času. V normal móde:

PríkazVýznam
iprepnúť do insert módu (písať)
Escvrátiť sa do normal módu
h j k lpohyb vľavo, dole, hore, vpravo
xzmazať znak pod kurzorom
:wquložiť a ukončiť
:q!ukončiť bez uloženia

Namiesto šípok používaj h j k l. Spočiatku to bude pomalé, ale po pár dňoch budeš rýchlejší ako s myšou.

26.5 vimtutor

Vim má vstavaný tutoriál. Stačí spustiť vimtutor a prejdeš si všetko krok za krokom priamo v termináli.

student@debian: ~
student@debian:~$ vimtutor =============================================================================== = Vitajte v tutoriáli VIM - Verzia 1.7 = = = = Vim je veľmi výkonný editor, ktorý má veľa príkazov... = = = =============================================================================== student@debian:~$

vimtutor je najlepší spôsob, ako sa naučiť vim. Prejdi si ho celý, zaberie to asi 30 minút a naučí ťa všetko podstatné.

Hodina 27 · Blok 6

tmux a vzdialená správa

Terminálový multiplexor, ktorý drží tvoje relácie nažive.

Teória 10 min Prax 30 min Úloha 10 min

27.1 Problém s odpojením

Keď sa pripojíš cez SSH a spustíš dlhý príkaz, čo sa stane, keď sa odpojíš? Proces zomrie, pretože bežal na popredí tvojej relácie.

Predstav si, že inštaluješ veľký balík, odpojíš sa na obed a po návrate zistíš, že inštalácia sa prerušila. tmux tento problém rieši.

27.2 Čo je tmux?

tmux je terminálový multiplexor. Vytvorí reláciu, ktorá beží nezávisle od tvojho pripojenia. Môžeš sa odpojiť, relácia beží ďalej, a keď sa vrátiš, pripojíš sa späť a vidíš presne to, čo si nechal.

tmux drží reláciu nažive
tmux drží tvoju reláciu nažive aj po odpojení SSH. Procesy v nej bežia ďalej, aj keď si offline.

27.3 Vytvor a pripoj reláciu

Novú reláciu vytvoríš tmux new -s názov. Odpojíš sa Ctrl+B a potom d. Znova sa pripojíš tmux attach.

student@debian: ~
student@debian:~$ tmux new -s praca # si vnutri relacie - dole vidis zeleny stavovy riadok # odpojis sa cez Ctrl+B a potom d [detached (from session praca)] student@debian:~$ tmux ls praca: 1 windows (created Tue Sep 8 10:30:01 2026) student@debian:~$ tmux attach -t praca student@debian:~$

Všimni si: tmux new -s praca reláciu vytvorí a hneď ťa do nej prepne - dole sa objaví stavový riadok. Von sa dostaneš klávesami Ctrl+B a potom d (detach), relácia beží ďalej. tmux ls ukáže bežiace relácie a tmux attach -t praca sa k nej vráti. Ak chceš reláciu vytvoriť a zostať mimo nej, použi tmux new -d -s praca.

27.4 Dlhý príkaz a odpojenie

Teraz to najdôležitejšie. Spustíme dlhý príkaz v tmux, odpojíme sa a znova pripojíme. Príkaz medzitým beží.

student@debian: ~
student@debian:~$ tmux new -s dlhy [v tmux relácii] student@debian:~$ sleep 60 && echo "hotovo" # stlač Ctrl+B a potom d pre odpojenie [detached (from session dlhy)] student@debian:~$ tmux attach -t dlhy hotovo student@debian:~$

Príkaz sleep 60 bežal 60 sekúnd. Medzitým sme sa odpojili a znova pripojili, a príkaz stále bežal a dokončil sa. Presne takto funguje tmux.

27.5 Rozdelenie okna

tmux ti umožní mať viac terminálov v jednom okne. Ctrl+B a % rozdelí okno vertikálne, Ctrl+B a " horizontálne. Prepínaš sa Ctrl+B a šípkou.

student@debian: ~
student@debian:~$ tmux new -s rozdelene [v tmux relácii] # Ctrl+B % -> vertikálne rozdelenie # Ctrl+B " -> horizontálne rozdelenie # Ctrl+B šípka -> prepínanie medzi panelmi student@debian:~$

V jednej polovici môžeš sledovať logy, v druhej písať príkazy. Je to ako viac okien terminálu, ale v jednom SSH pripojení.

Bezpečnosť a firewall

Základné pravidlá a ochrana systému firewallom.

28.1 Základné pravidlá bezpečnosti

Bezpečnosť nie je o jednom nástroji, ale o návykoch. Tri najdôležitejšie: aktualizuj systém, používaj silné heslá a spúšťaj čo najmenej služieb.

Každá otvorená služba je potenciálny vstup pre útočníka. Čím menej portov počúva, tým menšia plocha na útok. A aktualizácie opravujú známe diery, takže ich neodkladaj.

28.2 Firewall - čo to je?

Firewall je filter, ktorý rozhoduje, ktoré spojenia môžu prejsť do tvojho počítača. Predvolene môže blokovať všetko a ty povolíš len to, čo naozaj potrebuješ.

Neotváraj zbytočné porty
Neotváraj porty, ktoré nepotrebuješ. Každý otvorený port je potenciálny vstup pre útočníka. Povol len to, čo naozaj používaš.

28.3 UFW na Debiane a Minte

ufw (Uncomplicated Firewall) je jednoduchý firewall pre Debian a Mint. Zapneš ho, skontroluješ stav a povolíš SSH.

student@debian: ~
student@debian:~$ sudo ufw allow ssh Rules updated Rules updated (v6) student@debian:~$ sudo ufw enable Command may disrupt existing ssh connections. Proceed with operation (y|n)? y Firewall is active and enabled on system startup student@debian:~$ sudo ufw status Status: active To Action From -- ------ ---- 22/tcp ALLOW Anywhere 22/tcp (v6) ALLOW Anywhere (v6) student@debian:~$

Po zapnutí firewall blokuje všetko okrem povolených pravidiel. sudo ufw allow ssh povolí port 22, aby si sa mohol pripojiť cez SSH.

Najprv povoľ, až potom zapni
Poradie nie je náhodné. Ak si na stroji pripojený cez SSH a spustíš ufw enable skôr, ako povolíš port 22, odstrihneš sám seba a na vzdialený server sa už nedostaneš. Na serveri v datacentre je to problém za stovky eur. Pravidlo znie: allow najskôr, enable až potom.

28.4 Firewalld na Fedore

Fedora používa firewalld. Skontroluješ stav služby a vypíšeš aktívne pravidlá.

student@fedora: ~
student@fedora:~$ systemctl status firewalld ● firewalld.service - firewalld - dynamic firewall daemon Loaded: loaded (/usr/lib/systemd/system/firewalld.service; enabled) Active: active (running) student@fedora:~$ sudo firewall-cmd --list-all public (active) target: default services: dhcpv6-client ssh ports: student@fedora:~$ sudo firewall-cmd --add-service=http --permanent success student@fedora:~$ sudo firewall-cmd --reload success student@fedora:~$

firewall-cmd --list-all ukáže povolené služby. --add-service=http --permanent pridá HTTP natrvalo a --reload aplikuje zmeny.

28.5 Ako firewall blokuje port

Ukážeme si rozdiel. Keď je firewall vypnutý, port je otvorený. Keď ho zapneme bez povolenia, port sa zablokuje a spojenie zlyhá.

student@debian: ~
student@debian:~$ sudo ufw disable Firewall stopped and disabled on system startup student@debian:~$ nc -l 8080 & [1] 1234 student@debian:~$ ss -tln | grep 8080 LISTEN 0 1 0.0.0.0:8080 0.0.0.0:* student@debian:~$ sudo ufw enable Firewall is active and enabled on system startup student@debian:~$ ss -tln | grep 8080 LISTEN 0 1 0.0.0.0:8080 0.0.0.0:* # sluzba stale pocuva! ss ukazuje sokety, nie pravidla firewallu student@debian:~$

Toto je dôležité nedorozumenie, ktoré stojí za to pochopiť: ss ukazuje sokety, nie firewall. Služba počúva ďalej, firewall len zahadzuje pakety, ktoré k nej idú zvonku. Rozdiel teda neuvidíš z VM - musíš to skúsiť z iného stroja.

z hostiteľského PC, nie z VM
user@host:~$ nc -vz 192.168.1.10 8080 nc: connect to 192.168.1.10 port 8080 (tcp) failed: Connection timed out # to iste po "sudo ufw allow 8080" vo VM prejde: Connection to 192.168.1.10 8080 port [tcp/*] succeeded! user@host:~$

Aktívne pravidlá firewallu si vždy pozri cez sudo ufw status. To je jediný spoľahlivý zdroj toho, čo je povolené.

28.6 Ďalšie bezpečnostné tipy

Pár pravidiel, ktoré ťa ochránia na reálnom serveri:

  • Vypni root login cez SSH v /etc/ssh/sshd_config (riadok PermitRootLogin no).
  • Používaj silné heslá a SSH kľúče namiesto hesiel.
  • Buď opatrný so sudoers, neprideľuj zbytočné práva.
  • Pravidelne aktualizuj systém cez apt upgrade alebo dnf upgrade.
