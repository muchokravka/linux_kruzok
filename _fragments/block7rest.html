Hodina 30 · Blok 7

Vlastný systemd servis

Vytvoríme si vlastnú službu, ktorú vie systemd spúšťať, zastavovať a reštartovať.

Teória 10 min Prax 35 min Úloha 10 min

30.1 Rýchle zopakovanie systemd

V hodine 21 sme sa naučili ovládať hotové služby. Dnes si vytvoríme úplne vlastnú. systemd je správca služieb - vie ich spúšťať pri štarte, reštartovať pri páde a zaznamenávať ich výstup.

Základné príkazy už poznáš:

student@debian: ~
student@debian:~$ systemctl status ssh ● ssh.service - OpenBSD Secure Shell server Loaded: loaded (/lib/systemd/system/ssh.service; enabled) Active: active (running) student@debian:~$ systemctl restart ssh student@debian:~$ systemctl stop ssh && systemctl start ssh student@debian:~$

Dnes to posunieme ďalej: namiesto hotovej služby si napíšeme vlastný skript a vlastnú definíciu služby v systemd.

30.2 Náš skript

Najprv si pripravíme skript, ktorý bude naša služba spúšťať. Každých 5 sekúnd zapíše aktuálny čas do súboru v domovskom adresári.

Vytvoríme ho v /usr/local/bin - to je štandardné miesto pre vlastné programy.

student@debian: ~
student@debian:~$ sudo nano /usr/local/bin/casopis.sh
/usr/local/bin/casopis.sh
#!/bin/bash # Služba: každých 5 s zapíše čas do log súboru while true; do echo "$(date '+%F %T') - služba beží" >> /home/student/casopis.log sleep 5 done
student@debian: ~
student@debian:~$ sudo chmod +x /usr/local/bin/casopis.sh student@debian:~$ ls -l /usr/local/bin/casopis.sh -rwxr-xr-x 1 root root 119 sep 8 14:30 /usr/local/bin/casopis.sh student@debian:~$
Prečo /usr/local/bin?
Do /usr/local/bin patria programy, ktoré nainštaluješ ručne (nie cez apt/dnf). Odtiaľ ich vie spustiť každý používateľ bez toho, aby musel písať celú cestu.

30.3 Unit súbor

Teraz príde to hlavné - definícia služby pre systemd. Súbory služieb sú v /etc/systemd/system/ a majú príponu .service.

student@debian: ~
student@debian:~$ sudo nano /etc/systemd/system/casopis.service
/etc/systemd/system/casopis.service
[Unit] Description=Môj prvý vlastný servis After=network.target [Service] ExecStart=/usr/local/bin/casopis.sh Restart=always [Install] WantedBy=multi-user.target
SekciaRiadokVýznam
[Unit]DescriptionPopis služby (vidíš ho v status)
[Unit]AfterSpusti až potom, čo je sieť hore
[Service]ExecStartKtorý program sa spustí
[Service]RestartReštartovať vždy, keď skript spadne
[Install]WantedByPri ktorom "cieľe" sa služba spúšťa (multi-user = po prihlásení do systému)

30.4 Spustenie služby

Po vytvorení unit súboru musíš vždy povedať systemd, že sa zmenil: daemon-reload.

student@debian: ~
student@debian:~$ sudo systemctl daemon-reload student@debian:~$ sudo systemctl start casopis student@debian:~$ sudo systemctl enable casopis Created symlink /etc/systemd/system/multi-user.target.wants/casopis.service → /etc/systemd/system/casopis.service. student@debian:~$ systemctl status casopis ● casopis.service - Môj prvý vlastný servis Loaded: loaded (/etc/systemd/system/casopis.service; enabled) Active: active (running) Main PID: 4821 (casopis.sh) student@debian:~$
student@debian: ~
student@debian:~$ cat /home/student/casopis.log 2026-09-08 14:31:02 - služba beží 2026-09-08 14:31:07 - služba beží 2026-09-08 14:31:12 - služba beží student@debian:~$ sudo systemctl stop casopis student@debian:~$ systemctl is-active casopis inactive student@debian:~$ sudo systemctl start casopis student@debian:~$

Služba beží, loguje do súboru a vieš ju kedykoľvek zastaviť a spustiť. Všimnite si, že enable (spúšťa sa pri štarte) je iná vec ako start (spúšťa sa hneď teraz).

daemon-reload je povinný
Vždy, keď zmeníš unit súbor, musíš spustiť sudo systemctl daemon-reload. Inak si systemd pamätá starú verziu a tvoje zmeny sa neprejavia.
Pozor na nekonečný cyklus s Restart=always
Ak skript okamžite skončí s chybou a máš Restart=always, systemd ho bude reštartovať stále dokola. Nekonečný cyklus s sleep 5 je v poriadku, ale dávaj pozor, aby skript nemal logiku, ktorá okamžite zlyhá.
🏠 Domáca úloha
  1. Čo robí ExecStart a čo Restart=always v unit súbore?
  2. Prečo je daemon-reload povinný po zmene unit súboru?
  3. Načrtni, čo všetko treba na vlastný servis: skript, unit súbor, príkazy. Napíš postup v 5 krokoch.
  4. Čo sa stane, keď máš Restart=always a skript okamžite skončí s chybou? Aké je riziko?
Hodina 31 · Blok 7

Logovanie a monitoring

Kde Linux ukladá logy, ako ich čítať a ako sledovať stav systému.

Teória 10 min Prax 35 min Úloha 10 min

31.1 Prečo logovať?

Keď niečo nefunguje, logy sú prvé miesto, kam sa pozrieš. Log je záznam udalostí - kto sa prihlásil, ktorá služba spadla, čo sa dialo v systéme. Každý správca servera trávi čas čítaním logov.

V Linuxe sú logy na dvoch miestach: v /var/log (tradičné súbory) a v samotnom systemd (príkaz journalctl).

31.2 journalctl - logy systemd

journalctl číta logy, ktoré zbiera systemd. Je to najrýchlejší spôsob, ako zistiť, čo sa deje.

student@debian: ~
student@debian:~$ journalctl -n 15 -- Logs begin at sep 8 08:00:00, end at sep 8 14:35:00 -- sep 8 14:34:55 debian systemd[1]: Started casopis.service - Môj prvý vlastný servis. sep 8 14:35:00 debian casopis.sh[4821]: 2026-09-08 14:35:00 - služba beží student@debian:~$ journalctl -u casopis -- Logs begin at sep 8 08:00:00 -- sep 8 14:31:00 debian systemd[1]: Started casopis.service - Môj prvý vlastný servis. sep 8 14:33:12 debian systemd[1]: Stopped casopis.service. student@debian:~$ journalctl -u casopis -f # sleduje logy naživo, ukončí sa Ctrl+C student@debian:~$

-n 15 ukáže posledných 15 riadkov. -u casopis filter na konkrétnu službu. -f (follow) sleduje logy naživo - skvelé pri debugovaní.

31.3 Logy v /var/log

Súbory v /var/log sú tradičnejšie logy, písané priamo programami.

student@debian: ~
student@debian:~$ ls /var/log/ auth.log kern.log syslog apt/ nginx/ journal/ student@debian:~$ sudo tail -n 10 /var/log/auth.log sep 8 14:30:12 debian sudo: student : TTY=pts/0 ; PWD=/home/student ; USER=root ; COMMAND=/usr/bin/nano /usr/local/bin/casopis.sh sep 8 14:31:02 debian systemd-logind[401]: New session 5 of user student. student@debian:~$
SúborČo obsahuje
auth.logPrihlásenia, sudo, zmeny používateľov
kern.logSprávy z jadra, hardvér, ovládače
syslogVšeobecné systémové správy
apt/História inštalácií balíkov
nginx/Logy web servera (ktorý si postavil v hodine 29)
Prečo sudo?
Väčšina logov v /var/log je čitateľná len pre root. Bežný používateľ by ich mohol čítať a zistiť heslá alebo citlivé informácie o systéme.

31.4 logrotate - prečo logy nerastú donekonečna

Logy by bez starostlivosti rástli, až kým by nezaplnili disk. K tomu slúži logrotate - starý log sa po čase "otočí" (zazipuje a nakoniec vymaže).

student@debian: ~
student@debian:~$ ls /etc/logrotate.d/ apt nginx rsyslog sudo ufw student@debian:~$ cat /etc/logrotate.d/nginx /var/log/nginx/*.log { daily rotate 14 compress missingok notifempty } student@debian:~$

Preklad: logy nginx sa rotujú denne, ponechá sa 14 starých verzií, staré sa komprimujú. Nginx má vlastnú konfiguráciu, iné programy tiež.

31.5 Monitoring systému

Na sledovanie aktuálneho stavu systému slúži niekoľko príkazov, ktoré už poznáš. Poďme si ich dať dokopy:

student@debian: ~
student@debian:~$ uptime 14:35:12 up 6:35, 2 users, load average: 0.00, 0.01, 0.05 student@debian:~$ free -h total used free shared buff/cache available Mem: 3.8Gi 520Mi 2.8Gi 12Mi 500Mi 3.0Gi Swap: 2.0Gi 0B 2.0Gi student@debian:~$ df -h / Filesystem Size Used Avail Use% Mounted on /dev/sda6 19G 3.1G 15G 17% / student@debian:~$ watch -n 2 free -h # každé 2 sekundy obnoví výpis, ukončí sa Ctrl+C student@debian:~$

watch opakuje príkaz stále dokola s prestávkou - super na sledovanie, ako sa systém mení. uptime ukáže, ako dlho systém beží a akú má záťaž.

Prvý krok pri riešení problému
Keď ti niečo nefunguje: 1) systemctl status služba, 2) journalctl -u služba -n 50, 3) Google s presným textom chyby. Log ti vždy povie viac, než hádanie.
🏠 Domáca úloha
  1. Prečo sú logy pre správcu systému také dôležité? Uveď príklad situácie, keď ťa log zachráni.
  2. Vysvetli, čo robí journalctl -u sluzba, -n 50 a -f - čo každý prepínač pridá?
  3. Prečo existuje logrotate a čo by sa stalo, keby logy rotované neboli?
  4. Vymenuj aspoň 3 príkazy na monitoring systému a čo každý ukazuje.

Záverečný projekt

Postavíš si kompletného mini-servera s web stránkou, vlastnou službou, zálohou a firewallom.

Zadanie 10 min Samostatná práca 40 min Domáca úloha 10 min

32.1 Zadanie

Toto je tvoja skúška. Postavíš malý, ale funkčný server, ktorý používa všetko, čo sme sa za 31 hodín naučili. Na ďalšej hodine ho odprezentuješ.

Projekt má štyri časti. Prejdi ich postupne a každú otestuj, až potom pokračuj ďalej.

32.2 Časť 1: Web server

Nginx z hodiny 29 musí bežať a na localhost musí odpovedať tvoja vlastná stránka s tvojím menom, triedou a malým popisom.

student@debian: ~
student@debian:~$ systemctl is-active nginx active student@debian:~$ curl localhost | head -n 5 <!DOCTYPE html> <html lang="sk"> <head><title>Projekt Janka</title></head> <body> student@debian:~$

32.3 Časť 2: Vlastná služba

Služba uptime-log (vlastný názov si zvoľ) bude každú minútu zapisovať aktuálny uptime do súboru ~/uptime.log. Využiješ znalosti z hodiny 30.

/usr/local/bin/uptime-log.sh
#!/bin/bash while true; do echo "$(date '+%F %T') $(uptime -p)" >> /home/student/uptime.log sleep 60 done
student@debian: ~
student@debian:~$ sudo systemctl daemon-reload student@debian:~$ sudo systemctl start uptime-log student@debian:~$ sudo systemctl enable uptime-log student@debian:~$ systemctl is-active uptime-log active student@debian:~$

32.4 Časť 3: Záloha

Napíš skript zaloha.sh (z hodiny 17), ktorý zazipuje celý /var/www/html do priečinka ~/backup so zadným dátumom v názve. Skript spustíš ručne.

student@debian: ~
student@debian:~$ mkdir -p ~/backup student@debian:~$ sudo tar -czf ~/backup/web_$(date +%F).tar.gz /var/www/html student@debian:~$ ls -lh ~/backup/ total 12K -rw-r--r-- 1 root root 3.2K sep 8 14:40 web_2026-09-08.tar.gz student@debian:~$ tar -tzf ~/backup/web_2026-09-08.tar.gz var/www/html/index.html var/www/html/index.nginx-debian.html student@debian:~$

32.5 Časť 4: Firewall

Zapni firewall (z hodiny 28) a povol v ňom SSH a HTTP, aby si sa vedel k serveru pripojiť a aby šla stránka otvoriť.

Debian/Mint (ufw)
student@debian:~$ sudo ufw allow ssh student@debian:~$ sudo ufw allow 80 student@debian:~$ sudo ufw enable Firewall is active and enabled on system startup student@debian:~$ sudo ufw status Status: active 22/tcp ALLOW Anywhere 80/tcp ALLOW Anywhere student@debian:~$
Fedora (firewalld)
student@fedora:~$ sudo firewall-cmd --permanent --add-service=ssh student@fedora:~$ sudo firewall-cmd --permanent --add-service=http student@fedora:~$ sudo firewall-cmd --reload student@fedora:~$ sudo firewall-cmd --list-all public (active) target: default services: dhcpv6-client http ssh ports: student@fedora:~$

32.6 Dokumentácia

Vytvor README.txt v domovskom adresári a do neho napíš odpovede na tieto otázky:

  • Aký názov si dal svojej službe a čo robí?
  • Ako overíš, že web server beží?
  • Kde a ako sa robí záloha?
  • Ako sa volá tvoja služba v systemd a ako ju zastavíš?
Postupuj po krokoch
Nezvládneš všetko naraz. Poradie: web → služba → záloha → firewall → README. Každú časť otestuj hneď po dokončení, nekumuluj chyby na koniec.
Čo môžeš použiť
Všetko: man stránky, --help, svoje poznámky, skripty z minulých hodín. Čo nemôžeš: odpisovať od spolužiaka kompletné riešenie. Môžeš sa poradiť, ale kód si napíš sám - na prezentácii ťa nechám vysvetliť, ako to funguje.
🏠 Domáca úloha
  1. Naplánuj záverečný projekt na papier: 4 časti v poradí a ako každú otestuješ.
  2. Ktorá časť projektu je podľa teba najťažšia a ako ju chceš zvládnuť?
  3. Priprav si 2-minútovú prezentáciu: čo ukážeš a v akom poradí?

33.1 Prezentácia projektu

Každý z vás má 2 minúty. Premietame na tabuľu, ostatní pozerajú. Tvoj VM je pripravený, projekt beží, ty ho predvedieš.

student@debian: ~
student@debian:~$ systemctl status uptime-log --no-pager | head -n 6 ● uptime-log.service - Zapisuje uptime do logu Loaded: loaded (/etc/systemd/system/uptime-log.service; enabled) Active: active (running) Main PID: 5102 (uptime-log.sh) student@debian:~$ curl localhost <!DOCTYPE html> <html lang="sk"> <head><title>Projekt Janka</title></head> student@debian:~$ cat /home/student/uptime.log 2026-09-08 14:41:01 up 6 hours, 44 minutes 2026-09-08 14:42:01 up 6 hours, 45 minutes student@debian:~$

Odprezentuj štyri veci: web stránku (curl + otvor v prehliadači), službu (status + log), zálohu (ukáž .tar.gz a obsah) a firewall (status). Povedz aj jednu vec, ktorá ťa prekvapila alebo ktorej si nerozumel.

Skvelá práca
Postaviť funkčný server s vlastnou službou, web stránkou a zálohou je viac, než dokáže väčšina dospelých. Si na to hrdý - zaslúžiš si to.

33.3 Čo ďalej?

Kurz končí, ale Linux sa nekončí. Tu je pár nápadov, kam pokračovať:

  • Homelab - starý počítač alebo Raspberry Pi ako domáci server (Nextcloud, Plex, AdGuard)
  • Self-hosting - vlastný cloud, vlastné web stránky, vlastný email
  • Certifikáty - Linux Foundation, LPI Linux Essentials (prvá, ľahká certifikácia)
  • Pokročilé skriptovanie - awk, sed, jq, automatizácia kadečoho
  • Containery - Docker a pod, na čom beží moderný internet
  • Vyskúšaj inú distribúciu - Arch? Gentoo? Ventoy a USB kľúč s desiatimi ISO
Naše pravidlá z hodiny 1 stále platia
Pýtaj sa. Rozbíjaj si veci vo VM. Čítaj man stránky. Vždy si zapisuj. A hlavne: skús to sám, ešte predtým, než sa spýtaš.

33.4 Programovanie na Linuxe

Linux je rodiskom obrovskej časti moderného softvéru. Väčšina serverov, na ktorých beží internet, je programovaná práve na Linuxe. Ak ťa programovanie ťahá, tu je prehľad toho, čo ťa čaká.

CLI nástroje - kompilátory a jazyky priamo v termináli

Na programovanie nepotrebuješ nič navyše. Kompilátory a jazyky sú priamo v systéme: gcc/g++ pre C/C++, python pre Python a git na správu kódu je neoddeliteľnou súčasťou systému. Všetko ovládaš z terminálu, ktorý už dôverne poznáš.

student@debian: ~
student@debian:~$ python3 -c "print('Ahoj, Linux!')" Ahoj, Linux! student@debian:~$

GUI prostredia - vývojové nástroje s oknami

Ak chceš programovať s oknami, na Linuxe máš na výber z desiatok prostredí:

  • VS Codium - plne open-source odvodenina Visual Studio Code (ktorý má aj proprietárne časti a telemetriu Microsoftu), univerzálne, najpopulárnejšie
  • Eclipse - univerzálne, hlavne pre Javu
  • QT Creator - C/C++
  • Apache NetBeans - Java
  • Jupyter - Python, matematika a dáta
  • Thonny a PyCharm - Python
  • Code::Blocks - C/C++
  • MonoDevelop - .NET
  • Scratch - vizuálne programovanie pre úplný začiatok
  • Lazarus - Pascal
  • Arduino IDE - mikrokontroléry

Výhody Linuxu pre programátorov

  • Git na jeden príkaz - sudo apt install git a máš nástroj, na ktorom stojí celý open-source svet (Linux samotný sa vyvíja v gite)
  • Výborná podpora rôznych architektúr - toolchaining pre x86, ARM, RISC-V a ďalšie
  • Dokumentácia priamo v systéme - po sudo apt install manpages-dev ti man 3 printf vysvetlí funkciu z C bez otvorenia prehliadača
  • Filozofia "všetko je súbor" dáva programom jednotné rozhranie
  • Balíčkový systém nainštaluje všetky nástroje jedným príkazom
Skús to
Webový server z hodiny 29 je vlastne tvoj prvý "program" bežiaci 24/7. Programovanie je prirodzené pokračovanie kurzu - aj bash skripty z bloku 4 už programovanie sú!
